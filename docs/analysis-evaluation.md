# 解析、影响分析及评估

## 剧本解析

入口：剧本页面。支持粘贴文本和 UTF-8 TXT，最多50,000字、50场。Word、PDF、OCR未实现。

流程：模型调用 `submit_script` 返回结构化场次 → Pydantic校验 → 按顺序核对连续原文证据 → 核对字段是否出现在该场原文 → 展示人物、场地、道具、昼夜、内外景及待确认项 → 制片生成草稿 → 人工确认入库。

称呼仅做Unicode规范化、首尾空格清理和去重，不擅自合并“小雨”和“小雨同学”等别名。缺失条件保留待确认，未覆盖文本和已有同名场次提示核对。证据保存行号及原文，解析历史存为项目事件。

同一解析重复或并发生成草稿返回同一草稿；旧项目版本不能导入。取消草稿后要重新解析，不自动重新创建。入库场次保留原文、提取详情和待确认问题；筹备事项尚不自动逐条创建。字段格式和字面支持校验不能证明语义正确、完整或抗提示注入有效，需要人工核对。

接口：

- `POST /api/projects/{pid}/scripts/parse`：`text`、`source_name`、`base_revision`。
- `GET /api/projects/{pid}/scripts`：最近20次解析。
- `POST /api/projects/{pid}/scripts/{eid}/draft`：生成待确认草稿，不确认。

## 影响分析

入口：影响分析页面、单条记录按钮、待确认草稿按钮、Agent的 `analyze_impact` 工具。

输入：记录ID、资源名称，或待确认草稿ID；可携带项目版本。草稿必须处于当前版本且未处理。

以目标记录和规范化资源名称定位直接关联，再沿记录的 `scene_ids` 双向遍历，返回各受影响记录的路径。草稿中新旧资源均参与查找；资源记录额外按标题匹配。资源称呼仍依赖统一录入，不使用模糊匹配自动认定同一个实体。

通告只检查各版本中实际发布的拍摄安排及其场次、资源关联，不因为快照附带全部项目记录而把所有通告都算受影响。输出是需复核的潜在影响，不等于必定冲突；不替代排期检查，不自动改排期、不创建额外草稿、不发布通告。

接口：`POST /api/projects/{pid}/impact`。请求字段：`record_ids`、`resources`、`change_id`、`base_revision`，前三者至少一个。

## 离线评估

在项目目录执行：

```powershell
python -m evaluations.run
```

默认输出 `docs/evaluation-report.json`，也可指定 `--output`。失败返回非零退出码，报告包含场景名称、状态、耗时和失败信息。

覆盖场景：

- 解析原文证据、字段无依据拒绝、名称去重、缺失条件、未覆盖文本。
- 预览和草稿不修改正式事实、人工确认入库、重复及并发生成不重复、过期解析拒绝、跨项目隔离。
- 场次依赖路径、相关通告、无关记录排除、未知资源提示、新增排期草稿共用资源。
- Agent非法工具、非法参数、过期草稿的错误反馈和恢复。
- 原有事务、版本、幂等、排期检查及通告快照回归。

当前均在SQLite及模拟模型下执行。`contract_pass_rate`只表示这些业务契约的回归通过率。真实模型的场次召回率、字段准确率、证据定位正确率和人工修改量，需要用人工标注剧本另行测量；尚未进行真实付费模型调用和PostgreSQL验证。
